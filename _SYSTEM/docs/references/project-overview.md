## What It Is

AgentTeamDiscussions is a multi-agent AI deliberation platform. Structured teams of AI agents — each with distinct personalities, roles, and anti-sycophancy rules — debate design questions from a brief, then a neutral moderator synthesizes their responses into design documents.

Primary use case: overnight design spec generation. A human writes a brief with open questions; the system runs structured multi-round debates and outputs design docs + a Morning Brief summary by morning.

## How It Works

### Core Runtime Flow

```
User provides brief.md
  │
  ▼
session_runner.py
  │  ┌─────────────────────────────────────────────────────┐
  │  │ For each question in brief:                          │
  │  │                                                       │
  │  │  Round 1 (propose): cognitive_architect, flow_orch  │
  │  │    → Each agent speaks sequentially                  │
  │  │    → Each sees all prior speakers in this round      │
  │  │                                                       │
  │  │  Round 2 (critique): systems_pragmatist, adv_critic  │
  │  │    → Sees full Round 1 transcript as context         │
  │  │                                                       │
  │  │  Round 3 (evaluate): product_oracle, ctx_surgeon     │
  │  │    → Sees Rounds 1+2 as context                      │
  │  │                                                       │
  │  │  Synthesis: neutral moderator merges → design_doc    │
  │  │  Ledger extraction: DECIDED/OPEN items → ledger.md   │
  │  └─────────────────────────────────────────────────────┘
  │
  ▼
Morning Brief generated from decision ledger
```

### Key Design Principles

1. **Config-driven, not code-driven**: All experiment modes, timeouts, agent groupings, and prompt overlays are YAML. Adding a new mode = one YAML entry.

2. **Anti-sycophancy at the prompt level**: Every agent has `anti_slop` rules enforced in their system prompt (agreement tax, perspective lock, devil's advocate duty).

3. **Context chaining**: Each question's design doc is passed as context to subsequent questions (truncated to `prior_specs` limit).

4. **Crash-safe sessions**: Every file is written with a `<!-- complete -->` marker. On resume, incomplete files are re-run. Question list is integrity-checked via SHA-256 hash.

5. **Drift detection**: Between turns, agents are checked for agreement/capitulation phrases. If detected without identity anchor keywords, a drift reminder is injected.
