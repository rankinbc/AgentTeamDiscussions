# Architecture

**Analysis Date:** 2026-03-25

## Pattern Overview

**Overall:** Multi-layer pipeline architecture with a shared Python library (`agentteam`) consumed by discrete project applications.

**Key Characteristics:**
- All agent LLM calls go through a single subprocess wrapper (`agentteam.runner.claude`) that shells out to the `claude` CLI — no direct API client
- Agent identity is pure data (Pydantic `AgentConfig`); prompt construction is separate from data
- Sessions are crash-safe: every file write appends a `<!-- complete -->` marker; the runner checks markers before resuming
- Discussion modes are data-driven YAML, not code branches — adding a new experiment mode requires no Python changes
- The `agentteam` package is installable (`pyproject.toml`); engine project adds it to `sys.path` directly during development

## Data Flow

### Single-Agent Turn

1. Caller builds a `system_prompt` via `agentteam.prompts.builder.build_system_prompt(agent)` from the agent's `AgentConfig`
2. Caller builds a `payload` string: perspective reminder + context lens + discussion history + question text
3. `agentteam.runner.claude.run_claude_async(system_prompt, payload, timeout)` spawns the `claude -p` subprocess
4. Claude CLI writes response to stdout; runner reads and returns it as a plain string
5. Error responses are prefixed with `[` — checked via `is_error_response(response)` or string prefix test

### Multi-Agent Round (`discussion/engine.py:run_round`)

1. Speaking order computed by `compute_speaking_order()` — scored by `assertiveness * 0.5 + intensity * 0.3 + stubbornness * 0.2` plus jitter
2. Agents run sequentially by default: each agent receives `this_round_so_far` containing all prior speakers' text
3. Each agent response is appended to `this_round_so_far` before the next speaker is invoked
4. Callbacks (`on_agent_start`, `on_agent_done`, `on_agent_context`) fire for live UI streaming
5. Round responses collected in `dict[agent_key, str]`; health-checked (`check_round_health`) before proceeding

### Full Question Lifecycle (`discussion/engine.py:run_question`)

1. Load experiment mode from `config/experiment_modes.yaml` — determines which agents in which rounds
2. For each round group (`propose`, `critique`, `evaluate`, optional `counter`):
   a. Call `run_round()` with accumulated prior-round discussion as context
   b. Append round output to `accumulated_discussion` for next round
3. After all rounds: call `synthesize()` — single LLM call that merges all round responses into a design doc
4. Return `(design_doc, transcript)` tuple

### Session Lifecycle (`session/runner.py`)

1. Parse brief (`agentteam.brief.parser.parse_brief`) → `(decisions_text, questions_list)`
2. Create session directory: `_SYSTEM/projects/sessions/{YYYY-MM-DD_HHMM}_{brief-slug}/`
3. Write `config-snapshot.yaml` and `session_status.json`
4. For each question:
   a. Skip if `is_complete(question_file)` — supports crash recovery
   b. Call `run_question_with_cascade()` — wraps `run_question()` with per-round failure cascade
   c. Write per-round files: `questions/{NN}-{slug}-{round}.md` with completion marker
   d. Write `questions/{NN}-{slug}.md` (design doc) and `-transcript.md`
   e. Call `extract_ledger_from_doc()` — separate LLM call to extract `DECIDED:` / `OPEN:` entries
   f. Append to `decisions_ledger.md` via `append_to_ledger()`
   g. Update `session_status.json`
   h. Chain design doc forward as `prior_specs` context (truncated to `config.truncation.prior_specs` chars)
5. After all questions: `generate_morning_brief()` from ledger → `summary.md`
6. Optionally run evaluation via `evaluation/evaluator.py`

### Session Resume

1. `--resume {folder-name}` flag locates existing session dir
2. Loads `session_status.json` and re-parses brief
3. Hashes question list and compares to stored hash — rejects resume if brief changed
4. Skips questions where `is_complete()` returns true; re-runs the rest

## Error Handling

**Strategy:** Degrade gracefully rather than abort. LLM failures produce error strings, not exceptions, allowing partial results to be saved.

**Patterns:**
- `run_claude_async/sync` returns `[Error...]` prefixed strings on failure — never raises by default; callers check via `is_error_response()`
- `ClaudeError` hierarchy defined in `_SYSTEM/agentteam/runner/errors.py` for callers that prefer exceptions
- Round-level failure cascade in session runner: propose failure skips the question entirely; critique/evaluate failure saves whatever completed rounds exist
- `check_round_health()` requires at least one agent to succeed per round; individual agent failures are logged as warnings but do not abort the round
- Per-question status tracked in `session_status.json` with values: `complete`, `skipped`, `partial`, `failed`
- Circuit breaker: `health_checks.circuit_breaker_threshold` (default 3) consecutive failures stop the session
- Ledger extraction failure is non-fatal — logged but skipped; hallucination check validates ledger/doc ratio before appending

## Cross-Cutting Concerns

**History Truncation:** Both `Conversation` and `MultiConversation` apply sliding window truncation (configurable via `config/defaults.yaml`). Agent patience/receptivity further filters prior rounds via `filter_prior_rounds()`.

**Context Chaining:** Design docs from earlier questions chain forward as `prior_specs` (truncated to 6000 chars total). Open questions extracted from each doc also chain forward, giving later questions access to unresolved items.

**Anti-Slop Enforcement:** Per-agent rules (`AntiSlopConfig`) compile into system prompt sections — agreement tax, perspective lock, devil's advocate duty, uncomfortable idea quota, domain pivot trigger.

**Speaking Order Determinism:** Controlled randomness via `compute_speaking_order()` — personality-weighted score with ±0.1 jitter prevents identical ordering across runs without full randomness.
