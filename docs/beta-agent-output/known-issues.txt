 Problems I've seen with the agents so far:

  1. They produce code when asked for requirements. The synthesis prompt and question framing had to be rewritten twice because agents default to schemas, Pydantic models, and pseudocode instead of staying at the design level. The agent configs have nothing telling them
   what altitude to operate at.
  2. No awareness of each other. Each agent answers in isolation. The best output was the first panel discussion where they responded to each other's proposals. The generate_specs pipeline lost that -- 3 independent essays that reinvent the same things.
  3. No conversation memory across calls. Every claude -p call is stateless. The agents don't know what they said last time or what the other agents proposed. Context has to be manually stuffed into each call.
  4. Timeout problems from verbosity. Agents produce massive responses (150-330 lines) that hit the 180s-420s timeouts. There's nothing in their configs constraining output length or telling them to be concise.
  5. The synthesis step is the bottleneck. Feeding 3 long agent responses into a 4th synthesis call overwhelms it -- most synthesis calls timed out. The architecture of "panel then synthesize" doesn't scale when agents are verbose.
  6. No role differentiation on output type. All three agents answer every question the same way -- proposing full designs. The Skeptic should be poking holes, the Builder should be asking "what's the simplest version," but instead they all write comprehensive
  proposals.
  7. Anti-slop rules aren't tested. We have agreement tax, perspective enforcement, etc. in the YAML but haven't validated whether they actually change behavior. The agents still produce generic opener patterns despite the anti_patterns list.
  8. No feedback loop. When an agent produces filler or goes off-character, nothing corrects it. The "drift correction" concept from the Turn spec doesn't exist in the beta system.
