## Session Lifecycle (session/runner.py)

```
main()
  ├── parse CLI args
  ├── load brief → decisions, questions
  ├── hash question list (integrity key for resume)
  ├── create OR resume session_dir
  ├── load team + build system_prompts
  │
  ├── [optional] start live server thread
  │
  └── for each question:
        ├── run_question_with_cascade()
        │     ├── for each round:
        │     │     ├── run_round() (from discussion/engine.py)
        │     │     ├── check_round_health() — min response length check
        │     │     ├── write round file with completion marker
        │     │     ├── drain moderator message queue (if --live)
        │     │     └── failure cascade:
        │     │           propose fails → skip question
        │     │           critique/evaluate fails → save partial, no synthesis
        │     │
        │     └── synthesize() → design_doc
        │
        ├── extract_ledger_from_doc() — separate Claude call → DECIDED/OPEN
        ├── append_to_ledger() — write to decisions_ledger.md
        ├── write design doc + transcript with completion markers
        └── update session_status.json
  │
  └── generate_morning_brief() — summarize session from ledger
```

---

## Failure Cascade Rules

| Round that fails | Result |
|---|---|
| `propose` or `counter` | Skip entire question — `status: skipped` |
| `critique` | Save proposal round, stop — `status: partial` |
| `evaluate` | Save proposal + critique, stop — `status: partial` |
| synthesis | Save all rounds, skip doc — `status: synthesis_failed` |
| ledger extraction | Warn, skip ledger update — session continues |

Circuit breaker: 3 consecutive round failures → session stops.

## Config System

All behavior is tunable via YAML. **Never change Python to change behavior.**

### defaults.yaml

All timeouts, truncation limits, health check thresholds, conversation history limits.

Key values:
- `timeouts.discussion`: 420s per LLM call (structured rounds)
- `truncation.prior_specs`: 6000 chars max for context chaining
- `health_checks.min_response_length`: 20 chars
- `health_checks.circuit_breaker_threshold`: 3 consecutive failures

### experiment_modes.yaml

Each mode defines `groups` (round_name → [agent_keys]) and `agent_roles` (agent_key → overlay_key).

```yaml
compete:
  description: "Competitive vs Minimalist proposers"
  groups:
    propose: [cognitive_architect, flow_orchestrator]
    critique: [systems_pragmatist, adversarial_critic]
    evaluate: [product_oracle, context_surgeon]
  agent_roles:
    cognitive_architect: competitive
    flow_orchestrator: minimalist
```

### role_overlays.yaml

Per-role instruction fragments injected into agent payloads:
- `competitive` — maximize features, outcompete alternatives
- `minimalist` — cut ruthlessly, simplest solution wins
- `maximalist` — push scope, think 10x
- `contrarian` — challenge everything
- `operator` — practical, ship-it mindset
- `user_first` — everything through the lens of user value

### agent_display.yaml

Display names and hex colors per agent key. Used in terminal output and live dashboard.

## Live Dashboard (live/server.py)

SSE-based HTTP server on port 8899. Three-panel layout:
- **Left**: Agent roster with personality traits
- **Center**: Chat-style message stream
- **Right**: Agent detail panel (slides in on click)
- **Bottom**: Prompt inspector + moderator input bar

Events emitted: `round_start`, `agent_thinking`, `agent_context`, `agent_response`, `synthesis_start`, `synthesis_done`

**Moderator queue**: The UI has an input bar for moderator directives. Messages are queued and drained between rounds, injected as `[MODERATOR DIRECTIVE]` context items into the next round's accumulated discussion.

No external web framework — pure Python `http.server` + `BaseHTTPRequestHandler`.

## Evaluation (evaluation/evaluator.py)

LLM-based quality scoring. Reads design docs and transcripts from a session directory.

Scoring dimensions:
- **Transcript eval**: Argument quality, diversity, agent distinctiveness
- **Design doc eval**: Completeness, coherence, decision clarity
- **Agent eval**: Per-agent performance vs. their stated role

Supports single-experiment and multi-experiment comparison mode.
